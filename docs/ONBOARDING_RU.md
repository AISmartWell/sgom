# SGOM — Онбординг разработчика

**Платформа:** SGOM (AI Smart Well Inc.)
**Для кого:** входящий разработчик (full-stack / AI-интеграции)
**Цель:** за одну неделю — запускать, читать, расширять и сопровождать платформу.

---

## 1. Что такое SGOM

SGOM — веб-платформа аналитики нефтегазовых скважин. Она принимает сырые и «бумажные»
данные (спутниковые снимки, каротажные диаграммы, LAS-файлы, историю добычи, публичные
реестры), прогоняет их через фиксированный 9-стадийный пайплайн и выдаёт ранжированный
список скважин — лучших кандидатов на восстановление по технологии SPT
(Slot Perforation Technology, патент US 8,863,823), вместе с экономикой и заявкой на работы.

Ключевая идея: **детерминированный физический движок — источник истины, LLM — слой рассуждений.**
AI не выдумывает числа; он объясняет и ранжирует результаты наших собственных формул.

## 3. Карта репозитория

```
src/
  pages/               верхнеуровневые маршруты (Index, TechnicalSpec, SGOMTaskMap, ...)
  pages/modules/       по файлу на каждый модуль дашборда (~55 модулей)
  components/          UI, сгруппирован по фичам (geophysical/, spt/, ocr/, reserves-map/)
  components/ui/       примитивы shadcn — рестайлены, не форкать
  lib/                 детерминированная предметная логика (без React, тестируемо)
  hooks/               хуки данных (useWellRanking, ...)
  integrations/supabase/  автогенерируемый клиент и типы — не редактировать вручную
  workers/             web workers (Monte Carlo, 50k итераций)
supabase/functions/    edge-функции (по папке на функцию)
docs/                  архитектура и онбординг
```

### Файлы для чтения в первую очередь
1. `src/lib/petrophysics.ts` — ядро движка: Vshale, Archie Sw, проницаемость Тимура,
   сегментация литологии, типизация флюида, net pay.
2. `src/lib/pvt.ts`, `src/lib/material-balance.ts`, `src/lib/pore-pressure.ts` —
   цепочка пластового давления (Eaton → PVT-корреляция → Havlena–Ode).
3. `supabase/functions/spt-advisor/index.ts` — инжест кандидатов, AI-цикл, MCDA-скоринг.
4. `supabase/functions/geophysics-agent/index.ts` — экспертное AI-рассуждение поверх движка.
5. `src/hooks/useWellRanking.ts` — как ранжированный список попадает в UI.

## 4. 9-стадийный пайплайн (порядок фиксирован — не перенумеровывать)

1. Сканирование месторождения (спутник / региональный скрининг)
2. Классификация данных (инжест, AI-автозаполнение, OCR бумажных каротажей)
3. Керновый анализ (компьютерное зрение + интерпретация текста)
4. Накопительный анализ (IOIP, экономический лимит)
5. Сейсмическая интерпретация
6. SPT-проекция (кандидаты против критериев патента)
7. Экономический анализ (Monte Carlo, QAE)
8. Геофизическая экспертиза (петрофизический движок + AI-агент)
9. EOR-оптимизация (финальная рекомендация)

Каждый модуль показывает бейдж «Stage X» в заголовке.

## 5. Модель данных и безопасность

- Мультитенантность: у каждой предметной таблицы есть `company_id` — **всегда** валидировать.
- RLS включён на всех публичных таблицах + явные `GRANT` для `authenticated`
  и `service_role`. Таблица без грантов недоступна из приложения.
- Роли — в отдельной таблице `user_roles` (никогда не в профиле), проверка через
  функцию `has_role()` с `SECURITY DEFINER`. Неизвестные пользователи по умолчанию — `admin`;
  `demo@aismartwell.com` и инвесторские аккаунты получают ограниченный набор маршрутов.
- Без PostGIS: геопоиск — числовые lat/long с композитными индексами и bounding box.
- Регистрация отключена — только вход, аккаунты заводятся вручную.

## 6. Правила AI-интеграции

- Основной инференс: NVIDIA NIM через OpenAI-совместимый endpoint, секрет `NVIDIA_API_KEY`.
  Текущие модели: `nvidia/nemotron-3-super-120b-a12b` (основная),
  `nvidia/nemotron-3.5-lightning-30b-a3b` (резервная). NVIDIA быстро выводит hosted-модели
  из эксплуатации — ответ `410 Gone` означает просто замену id модели, это плановое обслуживание.
- Fallback: Lovable AI Gateway, тот же JSON-контракт, прозрачно для фронтенда.
- Каждый AI-вызов: жёсткий таймаут (AbortController, 45 с) + максимум 2 ретрая
  с экспоненциальной задержкой.
- Ответы парсятся защитно: убираем блоки `<think>`, markdown-ограждения, комментарии
  и висячие запятые перед `JSON.parse`; проверяем обязательные секции; при сбое — fallback.
- Детерминизм: никогда не использовать `Math.random()` в демо и синтетике — только `stableHash`.
- Происхождение данных всегда помечено: REAL DATA > FORMATION-BASED > SYNTHETIC.

## 7. Локальный workflow

```bash
npm install
npm run dev            # Vite dev-сервер на :8080
npx supabase functions deploy <name>   # деплой одной edge-функции
```

Переменные окружения (`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`,
`VITE_SUPABASE_PROJECT_ID`) управляются платформой — `.env` вручную не править.
Серверные секреты (`NVIDIA_API_KEY` и др.) хранятся в секрет-хранилище бэкенда
и доступны только внутри edge-функций.

## 8. Соглашения

- Тексты интерфейса — **строго на английском**; коммуникация в команде — на русском.
- Имперские единицы (ft, bbl, BOPD); удельное сопротивление — Ом·м.
- Цвета, градиенты и тени — семантические токены в `src/index.css`;
  никогда не хардкодить `text-white`, `bg-black` или `bg-[#hex]` в компонентах.
- Типографика: Space Grotesk (заголовки), Inter (основной текст), JetBrains Mono (технические подписи).
- Контейнерам Recharts нужен явный `minHeight`.
- Нейминг: платформа = **SGOM**, компания = **AI Smart Well Inc.** (только юридика/футер).

## 10. Владение и интеграции

Кодовая база принадлежит AI Smart Well Inc. Бизнес-логика живёт в edge-функциях и в
`src/lib`, поэтому в браузер она не попадает. Планируемая интеграция с маркетплейсом
Upstrima — это API/MCP-слой поверх существующего потока заявок —
см. `supabase/functions/mcp/` и `src/lib/mcp/`.
